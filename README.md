# Habits Tracker Project

Веб-приложение для трекинга полезных привычек, спроектированное на основе книги Джеймса Клира «Атомные привычки».  
Проект разработан на базе **Django REST Framework (DRF)** и содержит асинхронную систему фоновых напоминаний в **Telegram** с использованием **Celery**.  
Проект контейнеризирован и поддерживает автоматическое развертывание (CI/CD) в облачную инфраструктуру Yandex Cloud.

---

## Быстрый запуск проекта локально (Одной командой)

Для локального запуска всей инфраструктуры (Бэкенд, База данных, Брокер очередей, Планировщик и Веб-сервер) в изолированных контейнерах, вам понадобится установленный **Docker** и **Docker Compose**.

### Шаги запуска:

1. **Клонируйте репозиторий проекта на свой компьютер:**
   ```
   git clone https://github.com/AlexanderKokorinV/Habits_Tracker_Project
   cd Habits_Tracker_Project
   ```

2. **Создайте локальный файл окружения из шаблона:**
   ```
   cp .env.example .env
   ```
Файл .env должен обладать следующей структурой:

```
SECRET_KEY=my_SECRET_KEY #Ваш_SECRET_KEY
DEBUG=True

# Конфигурация базы данных
DB_NAME=my_data_base # Имя базы данных
DB_USER=username # Имя пользователя (например, postgres)
DB_PASSWORD=password # Пароль базы данных
DB_HOST=habits_db # Хост для базы данных
DB_PORT=5432 # Номер порта, который закреплен за PostgreSQL по умолчанию

# Настройки для Redis
REDIS_URL=redis://habits_redis:6379/0

# Настройки Celery и Telegram
CELERY_BROKER_URL=redis://habits_redis:6379/0
CELERY_RESULT_BACKEND=redis://habits_redis:6379/0

TELEGRAM_URL=https://api.telegram.org/bot # Базовая ссылка для работы с телеграм-ботом
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here # Ваш токен бота, полученный от @BotFather

# Настройка разрешенных адресов (Origins)
CORS_ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,https://read-only.example.com,https://read-and-write.example.com
CSRF_TRUSTED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,https://read-and-write.example.com
```

3. **Запустите проект командой:**
   ```
   docker compose up -d --build
   ```
Docker развернет изолированную сеть из **6 связанных сервисов**:
* `habits_db` — База данных PostgreSQL 16.
* `habits_redis` — Брокер сообщений Celery и кэш-хранилище.
* `habits_web` — Приложение Django DRF, запущенное через боевой WSGI-сервер Gunicorn.
* `habits_celery` — Асинхронный обработчик фоновых задач (отправка уведомлений в Telegram).
* `habits_celery_beat` — Планировщик периодических проверок привычек по расписанию.
* `habits_nginx` — Веб-сервер, раздающий статику и проксирующий внешние запросы к Django.

## Настройка CI/CD автоматизации (GitHub Actions)

В проекте настроен непрерывный конвейер интеграции и деплоя (CI/CD) через GitHub Actions (`.github/workflows/deploy.yml`). При каждом `git push` в ветку `main` запускается цепочка из трех стадий:

1. **Проверка кода (Lint):** Стиль кода автоматически сканируется линтером `Flake8` на соответствие стандартам PEP 8.
2. **Тестирование (Test):** Разворачивается тестовое окружение на базе Python 3.14 и прогоняется весь пакет модульных тестов Django.
3. **Деплой (Deploy):** В случае успеха GitHub Actions подключается к серверу Yandex Cloud по SSH, собирает Docker-образы, обновляет статику и применяет миграции СУБД.

### Как настроить автоматический деплой для своего сервера:

Для активации конвейера деплоя перейдите в настройки репозитория на сайте GitHub: **Settings** -> **Secrets and variables** -> **Actions** -> **New repository secret** и добавьте следующие секреты:

*   `SERVER_HOST` — Публичный IP-адрес виртуальной машины в Yandex Cloud.
*   `SERVER_USER` — Имя пользователя на удаленном сервере.
*   `SSH_PRIVATE_KEY` — Содержимое вашего секретного приватного ключа доступа.
*   `ENV_FILE` — Содержимое файла настроек `.env`.

## Бизнес-логика и валидаторы (Правила Джеймса Клира)
Бэкенд автоматически контролирует чистоту данных при создании/изменении привычек (`HabitSerializer`):
1. **Исключение дублирования наград:** Нельзя одновременно заполнить текстовое вознаграждение (`reward`) и связанную приятную привычку (`related_habit`).
2. **Правило двух минут:** Время выполнения атомной привычки (`duration`) ограничено 120 секундами.
3. **Чистота связей:** В качестве связанной привычки (`related_habit`) можно указывать только приятную привычку (с флагом `is_pleasant=True`).
4. **Приятная привычка самодостаточна:** У приятной привычки не может быть своего вознаграждения или своей связанной привычки.
5. **Регулярность выполнения:** Привычку нельзя выполнять реже, чем 1 раз в 7 дней (`periodicity <= 7`).

## Архитектура эндпоинтов

### Пользователи и Аутентификация (`users`)
* `POST /users/register/` — Регистрация (возвращает данные профиля и JWT-токены мгновенно).
* `POST /users/token/` — Логин (получение пары `access` и `refresh` JWT-токенов по Email и Password).
* `POST /users/token/refresh/` — Обновление `access`-токена.
* `GET/PUT/PATCH /users/profile/` — Управление личным профилем (привязка `telegram_chat_id` для получения уведомлений).

### Трекер Привычек (`habits`)
* `GET /habits/` — Список личных привычек пользователя (Пагинация: по 5 записей на страницу).
* `POST /habits/` — Создание атомной привычки (прогоняется через 5 валидаторов).
* `GET /habits/public/` — Список публичных привычек других пользователей системы.
* `GET/PUT/PATCH/DELETE /habits/{id}/` — CRUD-управление конкретной привычкой (доступно только владельцу).
* `POST /habits/{id}/check/` — Отметка о выполнении привычки для SPA-интерфейса (генерирует запись в `HabitLog`).
